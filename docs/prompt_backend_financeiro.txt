Você está no backend do BolluFlow e precisa suportar o novo módulo financeiro do frontend seguindo estas regras:

## Premissas obrigatórias
1. O backend é responsável pelos lançamentos automáticos.
2. O frontend NÃO deve disparar lançamento automático quando:
   - pedido é confirmado/entregue
   - compra/entrada de estoque de ingrediente ou insumo é registrada
3. O frontend só usa POST para lançamentos manuais.
4. Contrato da API financeira em inglês:
   - `POST /financial/entries`
   - `GET /financial/entries?type=income|expense`
   - `GET /financial/balance`

## O que já existe (inferido do frontend)
- Pedidos: `/orders`, `/orders/{id}`, `/orders/{id}/items`, `/orders/{id}/deliver`, etc.
- Ingredientes: `/ingredients` e conversões.
- Insumos: `/supplies` e conversões.
- Não há endpoint explícito de movimentação de estoque financeira nem endpoints `/financial/*` já usados no legado.

## 1) Modelo de dados recomendado

### 1.1 Tabela de movimentação de estoque (nova)
Criar uma entidade única para ingredientes e insumos.

Tabela sugerida: `stock_movements`
- `id` bigint PK
- `item_type` enum(`ingredient`,`supply`)
- `item_id` bigint not null
- `movement_type` enum(`purchase`,`adjustment`,`consumption`)
- `quantity` decimal(14,4) not null
- `unit_cost` decimal(14,4) not null
- `total_value` decimal(14,2) not null
- `notes` text null
- `event_key` varchar(120) null
- `created_at` timestamp
- `updated_at` timestamp

Índices:
- `(item_type, item_id, created_at)`
- `(movement_type, created_at)`
- `UNIQUE(event_key)` quando não nulo

### 1.2 Tabela financeira (nova)
Tabela sugerida: `financial_entries`
- `id` bigint PK
- `type` enum(`income`,`expense`) not null
- `amount` decimal(14,2) not null
- `description` varchar(255) not null
- `origin` enum(`order`,`ingredient_purchase`,`supply_purchase`,`manual`) not null
- `origin_id` bigint null
- `event_key` varchar(120) null
- `created_at` timestamp
- `updated_at` timestamp

Índices:
- `(type, created_at)`
- `(origin, origin_id)`
- `UNIQUE(event_key)` quando não nulo

## 2) Regras de negócio de derivação automática (backend)

### 2.1 Pedido confirmado/entregue
Ao marcar pedido como entregue (ou status equivalente de confirmação de venda):
- gerar `financial_entries` com:
  - `type = income`
  - `amount = total do pedido`
  - `origin = order`
  - `origin_id = id do pedido`
  - `description = Receita automática do pedido #<número/id>`
  - `event_key = order_delivered:<orderId>`

### 2.2 Compra/entrada de ingrediente ou insumo
Ao registrar movimentação de estoque do tipo `purchase`:
- se `item_type=ingredient` => `origin = ingredient_purchase`
- se `item_type=supply` => `origin = supply_purchase`
- gerar `financial_entries` com:
  - `type = expense`
  - `amount = total_value`
  - `origin_id = item_id`
  - `description = Despesa automática de compra ...`
  - `event_key = stock_purchase:<stockMovementId>`

### 2.3 Saldo
Sempre derivado no backend:
- `totalIncome = SUM(amount WHERE type='income')`
- `totalExpense = SUM(amount WHERE type='expense')`
- `balance = totalIncome - totalExpense`

## 3) Idempotência (obrigatório)
- Não duplicar lançamento para o mesmo evento.
- Usar `event_key` único para eventos automáticos.
- Em reprocessamento/retry do mesmo evento, retornar sucesso idempotente sem duplicar registros.

## 4) Endpoints que o frontend precisa

### 4.1 POST `/financial/entries`
Uso exclusivo para lançamento manual no frontend.

Request body:
```json
{
  "type": "income",
  "amount": 250.75,
  "description": "Ajuste manual"
}
```

Response 201:
```json
{
  "id": 101,
  "type": "income",
  "amount": 250.75,
  "description": "Ajuste manual",
  "origin": "manual",
  "originId": null,
  "createdAt": "2026-03-29T12:00:00.000Z"
}
```

Validações:
- `type` obrigatório: `income|expense`
- `amount` obrigatório e > 0
- `description` obrigatória

### 4.2 GET `/financial/entries?type=income|expense`
- Query `type` opcional
- Ordenar por `createdAt DESC`

Response 200:
```json
[
  {
    "id": 99,
    "type": "expense",
    "amount": 120.5,
    "description": "Despesa automática de compra de ingrediente",
    "origin": "ingredient_purchase",
    "originId": 12,
    "createdAt": "2026-03-29T11:00:00.000Z"
  }
]
```

### 4.3 GET `/financial/balance`
Response 200:
```json
{
  "totalIncome": 1000,
  "totalExpense": 420.5,
  "balance": 579.5
}
```

## 5) Compatibilidade e auditoria
- Os lançamentos automáticos devem existir mesmo quando a operação for feita fora do frontend.
- Recomendado manter log/auditoria de origem do evento.
- Se já existir estrutura semelhante no backend, reaproveitar ao invés de duplicar tabelas.
